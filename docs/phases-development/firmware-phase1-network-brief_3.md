# SempreIoT Firmware — Phase 1 Brief: Network Core (skeleton + provisioning + mesh + SAFR)

Target: **ESP32-S3** (`CONFIG_IDF_TARGET="esp32s3"` in both POC projects; classic-ESP32 per product is
still an open decision, see §14). **ESP-IDF v5.5.2** (the only toolchain, `CLAUDE.md`),
**espressif/mesh_lite 1.0.2** (pinned by `pocs/node/dependencies.lock`, pulls `iot_bridge 1.0.1`).

This phase builds the **permanent skeleton** of the official firmware and makes the **AC-device
network** work on it: board + AC nodes over Mesh-Lite, SAFR end to end, provisioning. **Battery
detectors (ESP-NOW leaves) are Phase 2** — nothing in Phase 1 sends or receives ESP-NOW; Phase 1 only
leaves the seams for it (§6.4). When Phase 1 is done it is **frozen**: later phases (leaves, sensing,
alarm engine, OTA, factory) add components that plug into the event bus and the SAFR dispatcher; they
do not edit Phase 1 files.

Decisions taken 2026-09-22 while reconciling: identity = `id` + `pop` strings (POC contract) in the
read-only `nvs_factory` partition; **`LEN ≤ 250`** (ESP-NOW limit) is now in the spec (§3 of
`protocol-safr-v3.md`, max payload 202); leaves out of Phase 1; implementation order in §15.

**Order of truth for this brief:** `docs/safr/protocol-safr-v3.md` (wire format, ACK/retry, timings) >
`docs/others/system-blueprint-v1.md` (behaviour) > `pocs/POC-BRIEF.md` + the round-1 code in
`pocs/{board,node,components}` (what was actually built and run on the bench) > this brief. Everything
below that used to be marked `[FROM POC]` or `[VERIFY]` has been replaced by what those sources say;
what none of them answers is collected in §14 and nowhere else.

**Reconciliation summary (what changed vs. the first draft of this brief):**

| Draft said | Reality (source) |
|---|---|
| Own frame: `VER 0x01`, LE, `MSG_ID` = message type, AES-256-GCM, IV `SRC‖NONCE‖MSG_ID`, no CRC | SAFR v3: `VER 0x03`, **big-endian**, 30-byte header = AAD, `MSG_TYPE` + per-sender `MSG_ID`, **AES-128-CCM**, nonce `SRC_MAC‖BOOT_CTR‖MSG_CTR`, CRC-16 over the whole frame (`protocol-safr-v3.md` §3–§5, `pocs/components/safr`) |
| Message IDs 0x0001–0x0104 (`HELLO`, `USB_*`, `LEAF_PAIR_*`…) | MSG_TYPE 0x01–0x0A + COMMAND 0x00–0x05/0x10/0x11. There is no `HELLO`, no `USB_*` family: the tablet link carries the same SAFR frames as every other hop (blueprint rule 7). Leaf messages are not in the spec yet (§14) |
| Payload "CBOR or packed struct — pick one" | **Fixed-layout packed structs, big-endian, sentinels `0xFF/0xFFFF/0x7FFF`** (spec §7, `put_u16/put_u32` in `node_safr.c`, `root_duties.c`) |
| Installation key HKDF-derived from "the code" string; SSID/channel/mesh_id derived by hash | "The code" is a **bundle** generated by the phone app and pushed as-is: `{system_id, net_ssid, net_psk, safr_psk[16], channel, mesh_id}`. Nothing is derived on the device (blueprint §0, `prov_types.h`, `installation_generator.dart`) |
| Dispatcher retries 3× at 200/400/800 ms | **3× with 2 s backoff, same MSG_ID, fresh MSG_CTR**, then local `COMM_FAULT` and keep going; ALARM re-announced every 60 s with `F_RETX` until `RESET` (spec §7.2/§9.1, `node_safr.c`) |
| Heartbeat 30 s, `HEARTBEAT_ACK`, node-side ONLINE/DEGRADED from acks | **HEARTBEAT 15 s / TOPOLOGY 60 s** for powered devices, leaf 60 s on wake; heartbeats are **never ACKed**; "missing" is decided by the supervisor after **3 × interval (45 s / 180 s)** (spec §9.2, blueprint §5.3) |
| TCP `:7240`, every node dials the board, NAPT questions | TCP **`192.168.4.1:5340`**, **only the root dials**; children use Mesh-Lite raw messages to the root; the board accepts exactly one client, newest wins (`tcp_link.c`, `node_mesh.c`) |
| Provisioning `SEMPRE-<serial>` + `POST /provision {code, name, proof}` ; board provisioned by `USB_SET_CODE` | `SIOT-SETUP-<id>` WPA2 = `pop`; `/info → /identify → /provision (CCM envelope) → /status`, `/enroll` on the board; **the board is provisioned from its sticker like any unit** (blueprint rule 4, `prov_http.c`) |
| USB framing "keep compatible or bump VER" | SAFR v3 bytes at **115200 8N1**, SOF+LEN+CRC resync, `CONFIG_ESP_CONSOLE_NONE`. VER stays `0x03` (`serial_link.c`, app `serial_provider.dart`) |

## 2. Project tree — `firmware/` (designed for growth, not just for Phase 1)

The tree is layered. Dependencies point **downwards only**; a component may include headers of the
layers below it, never of its siblings' private files, never of a layer above. The layers are real
directories, so a wrong include is visible in the path.

```
firmware/
  README.md                         # how to build / flash / test; this tree explained
  VERSION                           # single source of the firmware version string ("0.1.0"); read by CMake into siot_version
  apps/                             # one ESP-IDF project per image — thin: app_main() + Kconfig + partitions only
    board/                          # sempreiot-board (8 MB)                                  ← pocs/board
      CMakeLists.txt  sdkconfig.defaults  partitions_board.csv
      main/  app_main.c  Kconfig.projbuild  CMakeLists.txt  idf_component.yml
    node/                           # sempreiot-node (4 MB; one image for every AC node type)   ← pocs/node
      CMakeLists.txt  sdkconfig.defaults  partitions_node.csv
      main/  app_main.c  Kconfig.projbuild  CMakeLists.txt  idf_component.yml   (mesh_lite ==1.0.2)
  components/
    core/                           # layer 0 — pure C, no IDF drivers, builds on the linux target
      siot_safr/                    # SAFR v3: codec, CCM, CRC, counters, replay, dedupe, dispatcher   ← pocs/components/safr
      siot_evbus/                   # event bus (esp_event wrapper, one event base, typed event ids)   — new
      siot_version/                 # fw version string + build id; the "fw" field in /info and INSTALLATION
      siot_util/                    # put_u16/put_u32, hex, mac helpers, ring buffer                    ← node_safr.c / root_duties.c helpers
    platform/                       # layer 1 — everything that touches ESP-IDF drivers or NVS
      siot_board_def/               # pin map per model / hw_rev (generated from repo-root tools/pinmap/pinmap.yaml)
      siot_hal_gpio/  siot_hal_pwm/ siot_hal_serial/   # thin driver wrappers; only Phase 1 pins exist
      siot_identity/                # nvs_factory reader: id, pop, model, STA MAC                      ← siot_prov/prov_store.c (factory half)
      siot_config/                  # nvs "siot_inst": the code blob, name/zone, enrolled, boot_ctr, dev_seq   ← prov_store.c (installation half)
    net/                            # layer 2 — moves SAFR frames
      siot_link/                    # link_iface.h + backends: link_mesh (Mesh-Lite + root TCP), link_serial   ← node_mesh.c, tcp_link.c, serial_link.c
                                    #   Phase 2 adds link_espnow/ here without touching the others
      siot_netcore/                 # node side: emitter, fast-retry, re-announce, downlink dispatch, states   ← node_safr.c
      siot_coordinator/             # board side: root duties, device table, journal, INSTALLATION       ← root_duties.c, board_state.h, installation_msg.c
      siot_provisioning/            # setup SoftAP + HTTP contract + envelope crypto                     ← siot_prov (wifi_softap.c, prov_http.c, prov_crypto.c)
    ui/                             # layer 2 — human interface, depends on platform + core only
      siot_ui_led/                  # colour/pattern state machine                                       ← siot_led
      siot_ui_button/               # debounce, tap / double tap / hold → evbus events                   ← node_button.c, board_button.c
      siot_console/                 # esp_console commands (nodes only, CONFIG_SIOT_CONSOLE)
    features/                       # layer 3 — Phase 2+ plug-ins; EMPTY in Phase 1 except README.md
      README.md                     # the contract: a feature = one component, own Kconfig switch,
                                    #   registers SAFR handlers for NEW msg types, subscribes to evbus,
                                    #   exposes <name>_init() that app_main calls under #if CONFIG_SIOT_FEATURE_<X>
      (later) siot_leaf_espnow/  siot_sensing/  siot_alarm_engine/  siot_ota_client/  siot_ota_server/ ...
  test/
    host/                           # one linux-target IDF project; Unity; runs in CI on every commit
      main/  test_safr.c  test_vectors.c  test_replay.c  test_config.c  test_netcore.c
    hil/                            # hardware-in-the-loop: phase1.py drives 3–4 boards over UART + tablet log   ← built on tools/failover_timer.py
  ci/
    build.yml                       # idf.py build (both apps, size check: node ≤ 1.75 MB), host tests
tools/                              # repo root, shared by pocs/ and firmware/ (already there)
  make_sticker.py                   # {id, mac, pop} → nvs_factory CSV/bin + QR PNG
  failover_timer.py  capture-safr.sh
  pinmap/  pinmap.yaml  gen_board_def.py   # (new) → firmware/components/platform/siot_board_def
  flash.sh                          # (new) flash app + partition table + nvs_factory for one unit
```

Why it is shaped like this:

- **`apps/` are thin.** `app_main()` only wires components together in the boot order of §3. Every
  behaviour lives in a component, so a new product (siren, GPIO module) is a Kconfig choice inside the
  same `node` image, never a third project (OTA blueprint D1: two images only).
- **`core/` is host-testable.** It compiles for `idf.py --preview set-target linux`, so the wire format,
  counters, replay and dedupe are tested in CI without a board. `platform/` is the only place that
  includes `driver/*.h`, `nvs.h`, `esp_wifi.h`.
- **`siot_` prefix on every component** — IDF ships components called `console`, `log`, `nvs_flash`,
  `esp_wifi`…; an unprefixed `console/` would shadow IDF's and break the build.
- **`features/` is the freeze boundary.** Phase 1 = `core` + `platform` + `net` + `ui`, frozen at
  `fw-0.1.0`. Everything after Phase 1 is a directory under `features/` that registers itself; the
  `features/README.md` contract is what future sessions read before adding anything.
- **One public header per component** (`include/<name>.h`), private headers under `src/`, each
  component with its own `Kconfig` when it has options, and a `CMakeLists.txt` that lists
  `REQUIRES` only from lower layers. `EXTRA_COMPONENT_DIRS` in each app lists the five layer directories.
- **Version in one file.** `VERSION` → `siot_version` → `/info.fw`, `INSTALLATION`, console `id`, and the
  OTA manifest later. No hand-typed version strings anywhere else.
- `pocs/` and `mocked-device/` are copied from, never modified (`CLAUDE.md`); once `firmware/` builds,
  `CLAUDE.md`'s repo map gains `firmware/` and marks `pocs/` as reference-only.

sdkconfig facts that are not optional (from the POC `sdkconfig.defaults`): `CONFIG_MBEDTLS_HKDF_C=y`
(both), `CONFIG_MESH_LITE_ENABLE=y`, `CONFIG_FREERTOS_TIMER_TASK_STACK_DEPTH=4096`,
`CONFIG_ESP_TIMER_TASK_STACK_SIZE=4096` (node — Mesh-Lite overflows the 2048 default), and on the board
`CONFIG_ESP_CONSOLE_NONE=y`, `CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`, `CONFIG_BOOTLOADER_LOG_LEVEL_NONE=y`.

## 3. Boot sequence (both images)

```
app_main
 1. nvs_flash_init (erase + retry on NO_FREE_PAGES / NEW_VERSION_FOUND)
 2. fw_identity_init()        → id, pop, mac (ESP_MAC_WIFI_STA), model   (no id/pop → UNPROVISIONED_FACTORY, LED red slow)
 3. board_def_select(model, hw_rev) → pin map for this unit
 4. hal_gpio_init / hal_pwm_init (Phase 1 pins only)
 5. ui_led_init (shows BOOT pattern), ui_button_init (factory-reset hold armed in every mode)
 6. evbus_init
 7. config_load()             → siot_inst present? (the code blob) name/zone? enrolled list (board)?
 8. safr_init(system_id, safr_psk)   — only when a code exists
 9. console_init (nodes only, if CONFIG_SEMPRE_CONSOLE; never on the board's serial port)
10. role dispatch:
      no code → provisioning_start()                     (state SETUP, LED white blink)
      node    → link_mesh_start + netcore_start                 (state JOINING, LED white solid)
      board   → coordinator_start()                      (installation AP + TCP :5340 + serial link + root duties)
11. task watchdog: subscribe netcore/coordinator + ui tasks
```

Node top-level states (owned by `netcore`, published on the bus), derived from what the POC actually
observes (Mesh-Lite level, board socket, ACK outcome) — there is no `HEARTBEAT_ACK` to drive them:
`SETUP → JOINING (level 0) → ONLINE (level ≥ 1; root additionally has the TCP socket up) →
DEGRADED (root with the board socket down, or a critical EVENT that exhausted its 3 fast retries →
local TROUBLE COMM_FAULT) → OFFLINE (Mesh-Lite dropped to level 0)`
plus `FACTORY_RESET` (button ≥ 5 s) and `UNPROVISIONED_FACTORY` (no identity).

## 4. Identity and configuration

### 4.1 `siot_identity` (read-only, partition `nvs_factory`, namespace `siot_fact`)

Written by `tools/make_sticker.py` → `nvs_partition_gen.py` into the **`nvs_factory` partition** (OTA
blueprint §1: 0x8000, read-only in firmware, survives a full erase of `nvs`), never at runtime
(blueprint §2). The POC wrote the same namespace into the ordinary `nvs` partition — Phase 1 moves it;
the keys stay the POC's, as decided: `id` (string, ≤ 31), `pop` (string, 16..63 chars; the sticker
secret, the setup-network WPA2 password, the HMAC key of `/identify` and the HKDF ikm of the
`/provision` envelope). `model` comes from Kconfig (`CONFIG_SIOT_DEV_MODEL`, `"SIOT-BOARD-…"` prefix
identifies a board to the app wizard). Sticker QR payload: `{id, mac, pop}`. The OTA blueprint's
`serial / pair_key` scheme (§4.1 there) is superseded by this; that doc gets a one-line edit saying so.
Immutable id = `esp_read_mac(…, ESP_MAC_WIFI_STA)` (6 bytes) = `SRC_MAC` in every SAFR frame — the board
too, even though it runs AP-only.
The POC's Kconfig fallback for a missing `id`/`pop` (`CONFIG_SIOT_FACTORY_DEV_ID` / `_POP`) is **removed**
in Phase 1: no identity → `UNPROVISIONED_FACTORY`.
`dev_type` / `hw_rev` / `mfg_date` are not on the sticker or in NVS yet — §14.

### 4.2 `config` (runtime NVS, namespace `siot_inst`)

| Key | Type | Notes |
|-----|------|-------|
| `code` | blob `siot_installation_t` | `{system_id u16, net_ssid[32], net_psk[32], safr_psk[16], channel u8, mesh_id u8, name[33], zone[17]}` — the installation bundle exactly as `/provision` delivered it (`prov_types.h`) |
| `enrolled_n`, `enrolled` | u8, blob `siot_enrolled_entry_t[]` | board only: `{mac[6], name, zone}` from `POST /enroll`, ≤ 8 (`SIOT_MAX_ENROLLED`) |
| `boot_ctr` | u16 | **must be persisted and incremented on every boot** (spec §3/§4). The POC randomises it (`node_safr.c`, `root_duties.c`); Phase 1 fixes that |
| `dev_seq` | u16 | last EVENT sequence, persisted (spec §6). POC starts random; Phase 1 persists |

Nothing is derived from the code on the device: SSID, PSK, key, channel and mesh id are stored values
(`installation_generator.dart` creates them; `SYSTEM_ID` random ≠ 0, `NET_PSK` 16 alnum, `SAFR_PSK` 16
random bytes, `CHANNEL ∈ {1, 6, 11}`, `mesh_id = SYSTEM_ID & 0xFF` or 1). Factory reset = erase
`siot_inst`, keep `nvs_factory`, reboot into SETUP. Phase 2 adds the leaf keys (`role`, `parent_mac`)
to this namespace; Phase 1 does not define them.

## 5. SAFR — frame, crypto, dispatcher

### 5.1 Frame — SAFR v3 (`docs/safr/protocol-safr-v3.md` §3, `safr_proto.h`, `safr_frame.c`)

All multi-byte integers **big-endian**.

```
0   1  SOF 0xA5
1   1  VER 0x03
2   2  LEN        total frame length, SOF..CRC inclusive; receivers reject < 34 or > 256
4   1  MSG_TYPE   §5.4
5   2  MSG_ID     per-sender sequence; echoed by ACK; reused on fast retry
7   2  SYSTEM_ID  installation id; foreign → dropped before decrypt (counted "foreign")
9   6  SRC_MAC    sender STA MAC; central = 00:00:00:00:00:01
15  6  DST_MAC    FF:FF:FF:FF:FF:FF = uplink "to central" / downlink "all devices"
21  1  TTL        7 − level at origin (board: 7)
22  1  HOPS       level at origin (board: 0)
23  1  FLAGS      bit0 F_ENC (always set by firmware), bit1 F_ACK_REQ, bit2 F_RETX, bit3..7 = 0
24  2  BOOT_CTR   nonce component, ++ per boot (NVS)
26  4  MSG_CTR    nonce component, ++ per frame sent, reset per boot
--- header = 30 bytes = CCM AAD ---
30  N  PAYLOAD    ciphertext
30+N 16 TAG       AES-CCM tag
last 2 CRC16      CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF) over bytes 0..LEN-3
```

**`LEN ≤ 250`** (decided 2026-09-22, spec §3 updated): `SAFR_MAX_FRAME = 250`,
`SAFR_MAX_PAYLOAD = 250 − 30 − 16 − 2 = 202`. No existing message is affected (largest today: INSTALLATION
with two max-length entries ≈ 182 B payload). The POC still compiles with 256; `siot_safr` uses 250. The codec is transport-agnostic and identical on every
hop (serial, TCP, Mesh-Lite raw message, later ESP-NOW): `safr_build_frame(...)` /
`safr_parse_frame(buf, len, &rx)`. Appendix A of the spec has three deterministic vectors (65/68/76
bytes) that the firmware must reproduce byte-for-byte; they go into `test/host`.

### 5.2 Crypto (spec §4, `safr_frame.c`)

- **AES-128-CCM** via `mbedtls_ccm_encrypt_and_tag` / `mbedtls_ccm_auth_decrypt`, 16-byte tag.
  Key = the installation's `safr_psk` (16 bytes, from the code). One shared `mbedtls_ccm_context`
  behind a mutex (TX task and RX task both use it).
- **Nonce (12 bytes) = `SRC_MAC(6) ‖ BOOT_CTR(2) ‖ MSG_CTR(4)`** = header bytes 9..14 ‖ 24..29. Nothing
  extra travels on the wire. Retransmissions always use a fresh `MSG_CTR`.
- AAD = the full 30-byte header. Relays and the board forward frames **unchanged** and never
  re-encode them (the board only observes `SRC_MAC` / `MSG_TYPE` for its device table and journal).
- `F_ENC = 0` frames are a bench-only facility; production receivers reject them (`plaintext_rejected`).
- **Replay protection (spec §4):** receiver stores the last `(BOOT_CTR, MSG_CTR)` per `SRC_MAC`; a lower or
  equal pair from the same boot is a replay → diagnostic, no state change, no ACK. Today only the
  app implements this; the board (control unit) must implement it in Phase 1. Wrong `safr_psk` →
  CCM fails → "auth failed" diagnostic (with `SYSTEM_ID` matching = key-mismatch trouble).
- Site separation is two-layered: `net_psk` keeps foreigners off Wi-Fi, `SYSTEM_ID` + `safr_psk` keep
  their frames out (blueprint §7 table).

### 5.3 Dispatcher and ACK semantics (spec §7.2, §7.5, §9.1; `node_safr.c`, `root_duties.c`)

`safr_register(msg_type, handler, ctx)`; `safr_send(link, dst, msg_type, payload, len, flags)`.
Handlers run in the `net_task` context and must not block; they post to the bus or their own queue.

- **Who sets `F_ACK_REQ`:** EVENTs with severity ALARM or TROUBLE (mandatory); all central downlink
  except `EVENT_LOG_REQ`; the POC also sets it on the bench `MANUAL_TEST` ALERT (POC-BRIEF §4.3) —
  keep that for Phase 1 so the walk test is confirmed end to end.
- **Who ACKs:** the central ACKs every uplink frame carrying `F_ACK_REQ`. The **board ACKs every
  downlink `COMMAND` / `TIME_SYNC` locally** (`SRC_MAC` = board MAC) *and* forwards the raw frame into the
  mesh; the addressed node ACKs it again on its own behalf (uplink ACK with FLAGS = 0). `EVENT_LOG_REQ`
  and `GET_INSTALLATION` are answered by the board only, never forwarded, and get no separate ACK —
  the reply is the confirmation. ACK frames never set `F_ACK_REQ`. `HEARTBEAT`, `TOPOLOGY`,
  `NAME_ANNOUNCE` are never ACKed.
- **Fast phase:** un-ACKed → retransmit up to **3 × with 2 s backoff, same `MSG_ID`, fresh `MSG_CTR`**
  (`RETRY_BACKOFF_MS 2000`, `RETRY_MAX 3`). Still un-ACKed → local `TROUBLE COMM_FAULT`, keep going.
- **Re-announce phase (ALARM only):** every **60 s** (`ALARM_RETX_MS`) re-send the EVENT with fresh
  `MSG_ID`/`MSG_CTR`, **same `DEV_SEQ`**, `F_RETX | F_ACK_REQ`, until `COMMAND RESET`. A leaf in alarm
  never sleeps.
- **Dedupe:** EVENTs by `(SRC_MAC, DEV_SEQ)`; everything else by `(SRC_MAC, MSG_ID)` within 30 s
  (`node_mesh.c`: 16-entry table, `DEDUP_TTL_MS 30000`). Process once, ACK every time.
- Scheduler tick 250 ms (`STEP_MS`); one in-flight critical uplink per node in the POC — Phase 1 makes
  it a small queue with ALARM frames at the head (spec §0 severity priority).

### 5.4 Phase 1 message set (spec §7; `safr_proto.h`)

| MSG_TYPE | Name | Dir | Payload (fixed layout, big-endian) |
|----------|------|-----|------------------------------------|
| 0x01 | `EVENT` | uplink | 17 B: `EVENT_TYPE, EVENT_CODE, TIMESTAMP u32, PWR_FLAGS, BATTERY_PCT, SMOKE u16, TEMP i16×10, HUMIDITY, FAULT_FLAGS, FAULT_CODE, DEV_SEQ u16`. Phase 1 codes: `MANUAL_TEST 0x04` (ALERT 0x02, tap), `SMOKE_ALARM 0x01` (ALARM 0x03, bench double tap), `COMM_FAULT 0x09` (TROUBLE 0x04), `RESTORE 0x0B`. PWR_FLAGS on an AC device = `AC_OK|CHARGING`; sensor fields = sentinels |
| 0x02 | `HEARTBEAT` | uplink | 20 B: `TIMESTAMP u32, UPTIME_S u32, PWR_FLAGS, BATTERY_PCT, TEMP i16, RSSI_TO_PARENT i8, PARENT_MAC[6], LAYER`. Node: `PARENT_MAC`/RSSI from `esp_wifi_sta_get_ap_info()` (root → the board's AP), `LAYER` = Mesh-Lite level. Board shim: `LAYER 0`, `PARENT_MAC` = central, RSSI `0x7F` |
| 0x03 | `TOPOLOGY` | uplink | 14 + 7·n B: `TIMESTAMP, NODE_ROLE (0 root/1 node/2 leaf), LAYER, PARENT_MAC[6], RSSI_TO_PARENT, CHILD_COUNT, {CHILD_MAC[6], CHILD_RSSI}[n]`. Children = `esp_wifi_ap_get_sta_list()` (direct children, real RSSI). Board shim: role root, layer 0, children = every AC device heard since boot (a 180 s `CHILD_TIMEOUT_MS` is defined but not applied yet), RSSI `0x7F` |
| 0x04 | `ACK` | both | 4 B: `ACKED_MSG_ID u16, STATUS (0 OK / 1 ERROR / 2 UNKNOWN_DST), 0` |
| 0x05 | `COMMAND` | downlink | `CMD, ARG_LEN, ARGS`: `0x00 LINK_CHECK` (board ACKs; nodes ignore), `0x01 SILENCE`, `0x02 TEST` (→ MANUAL_TEST), `0x03 RELAY_SET`, `0x04 IDENTIFY {seconds}` (LED blue blink, default 3 s), `0x05 RESET` (stop re-announce, clear alarm LED), `0x10 GET_INSTALLATION` (board only, serial only), `0x11 SET_INSTALLATION` (Case B — ARGS undefined, §14) |
| 0x06 | `TIME_SYNC` | downlink | 5 B: `EPOCH u32, TZ_OFFSET_QH i8`. Central sends on link-up and hourly; board ACKs + forwards; nodes adopt the epoch (`s_epoch_base`) |
| 0x07 | `EVENT_LOG_REQ` | downlink | 5 B: `SINCE_JRN_SEQ u32, MAX_COUNT` (0 = 32). Board answers from its journal; no `F_ACK_REQ` |
| 0x08 | `EVENT_LOG_DATA` | uplink (board) | 28 B: `JRN_SEQ u32, LOG_FLAGS (bit0 LAST, bit1 EMPTY), ORIG_SRC_MAC[6], EVENT payload[17]` |
| 0x09 | `INSTALLATION` | uplink (board → central, serial only) | ≤ 208 B: `SYSTEM_ID, CHANNEL, NET_SSID_LEN+NET_SSID, NAME_LEN+NAME, ENROLLED_COUNT, {MAC[6], NAME_LEN+NAME, ZONE_LEN+ZONE}[m]` — **never** `net_psk` / `safr_psk` |
| 0x0A | `NAME_ANNOUNCE` | uplink | ≤ 50 B: `NAME_LEN+NAME (≤32), ZONE_LEN+ZONE (≤16)`; sent once after boot, retried each tick until a live transport accepts it |

There is no separate "USB" message family and no device-list message: the tablet builds its registry
from `HEARTBEAT`/`TOPOLOGY`/`NAME_ANNOUNCE` plus `INSTALLATION`, exactly as it does today. Leaf pairing
messages are Phase 2 (§6.4, §14 item 15).

Counters per sender (`node_safr.c`, `board_state.h`): `msg_id` ++ per new transmission group,
`msg_ctr` ++ per frame built, `dev_seq` ++ per distinct EVENT, `boot_ctr` per boot (persist — §4.2).

## 6. Link layer

### 6.1 Installation parameters (all carried in the code, none derived)

```
system_id   u16 ≠ 0                        (0x0000 reserved = unprovisioned; dev/mock 0x5346)
net_ssid    "SIOT-<4 hex>"                 (board installation AP; app-generated — blueprint says "<SYSTEM_ID hex>", see §14)
net_psk     16 random alnum chars          (WPA2-PSK of the board AP and of every node's own SoftAP)
safr_psk    16 random bytes                (AES-128-CCM key, §5.2)
channel     1 | 6 | 11                      (board AP and every node SoftAP are pinned to it; ESP-NOW leaves need it)
mesh_id     u8 = system_id & 0xFF (or 1)   (esp_mesh_lite_config_t.mesh_id)
```

Board AP: `net_ssid`/`net_psk`, WPA2, `channel`, hidden = false, `max_connection = 8`
(`BOARD_MAX_CHILDREN`), static `192.168.4.1`, DHCP on (`esp_netif_create_default_wifi_ap` defaults).
The channel is honoured by both sides because it is set explicitly in every `wifi_config_t.ap`
(`board_main.c`, `node_mesh.c`); Mesh-Lite's STA side follows whatever parent it associates to.

### 6.2 `link_iface.h` — the only thing `netcore` / `coordinator` see

```c
typedef enum { LINK_MESH, LINK_SERIAL /* Phase 2: LINK_ESPNOW */ } link_kind_t;
typedef void (*link_rx_cb_t)(link_kind_t k, const uint8_t *frame, size_t len, void *ctx);
typedef struct {
    esp_err_t (*start)(void);
    esp_err_t (*stop)(void);
    esp_err_t (*send)(const uint8_t *dst_mac, const uint8_t *frame, size_t len);   /* raw SAFR frame */
    bool      (*is_up)(void);
    int       (*rssi)(void);
} link_ops_t;
esp_err_t link_register(link_kind_t k, const link_ops_t *ops);
esp_err_t link_set_rx(link_rx_cb_t cb, void *ctx);
```

Every backend delivers whole frames: byte-stream backends (serial, TCP) reassemble with the same
loop everywhere (`reassemble_and_dispatch` in `tcp_link.c` / `node_mesh.c` / `board_main.c`): scan for
`0xA5`, read `LEN`, reject `< 34` or `> 256`, wait for `LEN` bytes, `safr_parse_frame` (CRC + SYSTEM_ID
+ CCM); on failure **discard one byte and rescan**. Accumulator `2 × SAFR_MAX_FRAME`, reset on overflow.

### 6.3 `link_mesh` (AC devices) — ESP-Mesh-Lite 1.0.2, as brought up in `node_mesh.c`

Init sequence (mirrors `managed_components/espressif__mesh_lite/external_examples/no_router`):
`esp_netif_init` → `esp_event_loop_create_default` → `esp_bridge_create_all_netif()` (SoftAP with DHCP +
STA netifs, `esp_wifi_init/start`) → `esp_bridge_wifi_set_config(WIFI_IF_STA, {0})` →
`esp_bridge_wifi_set_config(WIFI_IF_AP, {ssid = "<net_ssid>-<mac[3..5] hex>", password = net_psk,
channel})` → `ESP_MESH_LITE_DEFAULT_INIT()` with `mesh_id`, `max_level = 4`,
**`join_mesh_ignore_router_status = true`**, `softap_ssid/password` → `esp_mesh_lite_init` →
`esp_mesh_lite_set_softap_info` → `esp_mesh_lite_set_router_config({net_ssid, net_psk})` →
`esp_mesh_lite_raw_msg_action_list_register` → `esp_mesh_lite_start` →
`esp_wifi_set_inactive_time(WIFI_IF_STA, 6)`.

Facts that came out of the bench and are now rules:

- **Each node's SoftAP SSID must differ from the board's** (suffix = last 3 STA-MAC bytes). Mesh-Lite
  treats `net_ssid` as "the router"; a child that found a sibling under that SSID elected itself root.
  Password = `net_psk`; parents are found by Mesh-Lite's vendor IE / mesh id, not by SSID.
- **No `esp_mesh_lite_set_allowed_level()`** — it pins a node to a level and defeats failover. Root =
  whichever node Mesh-Lite puts at level 1 (`esp_mesh_lite_get_level() == 1`).
- **Mesh survives the board:** `join_mesh_ignore_router_status = true`. With the default (false) a root
  that loses the router drops its role and every child detaches; on the bench the whole network went
  idle when the board was switched off. With it true the nodes keep the tree, elect a root among
  themselves, and self-reference re-homes the best node onto the board when it reappears.
- **Parent-loss detection:** the driver's default beacon timeout was 25 s and was most of the failover
  time; `esp_wifi_set_inactive_time(STA, 6 s)` (min 3 s) shortens it.
- **Uplink:** root → straight onto the board TCP socket; child →
  `esp_mesh_lite_send_msg(ESP_MESH_LITE_RAW_MSG, {msg_id = 0x53414652 "SAFR", max_retry = 0,
  raw_resend = esp_mesh_lite_send_raw_msg_to_root})`. Mesh-Lite forwards hop-by-hop to the root; the
  root's `raw_process` callback for that id writes the bytes to TCP unchanged. `max_retry = 0` always
  — retries are SAFR's own (blueprint rule 8; never `esp_mesh_lite_try_sending_msg`).
- **Downlink:** root reads TCP → parse → dedupe `(SRC_MAC, MSG_ID)` 30 s → hand to `netcore` → re-broadcast
  with `esp_mesh_lite_send_broadcast_raw_msg_to_child` under id `0x53414644 "SAFD"`. **Every** node that
  receives a downlink frame does the same (act if `DST_MAC` is mine or broadcast, then re-broadcast to
  its own children). Whether Mesh-Lite propagates the broadcast beyond one level by itself was never
  confirmed; the re-broadcast + dedupe makes it correct either way, so it stays.
- **Transport to the board: one TCP session, root-initiated, to `192.168.4.1:5340`**. Non-blocking
  `connect()` + `select()` bounded at **3 s** (a blocking connect sat ~60 s on unanswered SYNs right after
  failover), reconnect backoff **2 s**, keepalive **idle 5 s / interval 2 s / count 3** (dead board
  noticed in ~11 s), `SO_RCVTIMEO 1 s` so the loop re-checks the root role. Frames are delimited by
  `SOF` + `LEN` (+ CRC), no extra length prefix. Depth-2 nodes never dial anything — the "root relay"
  is the design, not a fallback, so Mesh-Lite NAPT is irrelevant to SAFR.
- Root change: the old socket dies (keepalive), the new root dials; the board's `select()` loop accepts
  the newest client and drops the previous one. `netcore` treats the gap as `DEGRADED`, not a failure.
  Bench observation: the 25 s beacon timeout was most of the failover time before the inactive-time
  and connect-timeout fixes; no measured series was recorded (`pocs/RESULTS.md` was never written — §14).

### 6.4 Seams left for Phase 2 (ESP-NOW battery detectors) — no code in Phase 1

Phase 1 does not implement, link or test ESP-NOW. It only guarantees that adding it later does not
reopen frozen files:

- `link_kind_t` and `link_register()` accept a third backend (`LINK_ESPNOW`) without signature changes.
- `siot_netcore` and `siot_coordinator` forward any authenticated frame regardless of which link it
  came from — a leaf's frame relayed by its parent needs no special path (there is no `RELAYED` flag in
  SAFR v3; `TTL`/`HOPS` are the diagnostics).
- `PWR_FLAGS` bit 0 (`AC_OK`) is read from GPIO 5 and reported; the role switch it will drive is Phase 2.
- `LEN ≤ 250` is already enforced, so every Phase 1 frame is ESP-NOW-legal.
- The blueprint's leaf design (`PARENT_PROBE` / `PARENT_OFFER`, ACK `PENDING` bit 0x04, parent mailbox,
  leaf HEARTBEAT ACKed by its parent) is **specified since 2026-09-28 in protocol §12 (v3.4)** — 60 s
  fixed cadence, 9-byte leaf ACK, custody + outbox, alarm broadcast fallback. Plan:
  `docs/phases-development/phase2-leaf-brief.md`. Not a Phase 1 item.

### 6.5 `link_serial` (board ↔ tablet)

- Same SAFR v3 frames as every other hop; **115200 8N1**, raw binary, no inter-frame delimiter
  (`serial_provider.dart` opens the port at 115200; `usb_serial` plugin). `VER` stays `0x03`.
- Peripheral behind one Kconfig choice (`board/main/Kconfig.projbuild`): `CONFIG_SIOT_SERIAL_LINK_USB_SERIAL_JTAG`
  (product: GPIO 19/20, `usb_serial_jtag_driver_install`, rx 2048 / tx 4096) or
  `CONFIG_SIOT_SERIAL_LINK_UART0` (round-1 bench: GPIO 43/44 explicitly via `uart_set_pin`, UART driver,
  never stdout/VFS — the LF→CRLF translation was the SAFR v1 bug). Only `serial_link.c` changes between
  the two; the three-function API (`init/send/recv`) is the whole surface.
- Board sdkconfig keeps every text output off both peripherals (`CONFIG_ESP_CONSOLE_NONE`,
  `_SECONDARY_NONE`, `BOOTLOADER_LOG_LEVEL_NONE`); the ROM boot banner still precedes the stream on
  UART0 and the app's reframer resyncs on `SOF` + `LEN` + CRC.
- The app's USB link is "connected" only while a CRC+auth-valid frame arrived within the last 10 s; the
  central sends `LINK_CHECK` every 30 s and raises a link trouble after 3 unconfirmed (spec §9.3).
- Throughput was never measured and the native USB-Serial-JTAG path has not run against the app on
  real hardware (bench = UART0) — §14.

## 7. Provisioning (every unit, board included) — from `pocs/components/siot_prov`

1. Unprovisioned unit (`siot_inst` empty) or button held ≥ 5 s: **setup mode**. SoftAP
   **`SIOT-SETUP-<id>`, WPA2, password = `pop`**, channel 6, max 4 STA, `192.168.4.1`, `esp_http_server` on
   port 80, LED **white blink**. AC units keep it up indefinitely; the blueprint's 10-minute timeout is
   for battery units only.
2. Installer app scans the sticker QR → `{id, mac, pop}`; joins the setup network programmatically.
3. HTTP contract (`prov_http.c`; `name` ≤ 32 bytes UTF-8, `zone` ≤ 16):
   - `GET /info` → `{id, mac, model, fw, state, nonce}` — `nonce` = 16 random bytes hex, regenerated per call.
   - `POST /identify {id, proof}` — `proof = hex(HMAC-SHA256(key = pop, msg = nonce))` → `200 {ok}` / `403 proof_mismatch`.
   - `POST /provision {envelope, name, zone, epoch}` — `envelope = base64(nonce2(12) ‖ AES-128-CCM(key =
     HKDF-SHA256(ikm = pop, salt = nonce, info = "siot-prov-v1", 16 B), nonce2, aad = id, code_json) ‖
     tag16)`; `code_json = {system_id, net_ssid, net_psk, safr_psk_hex, channel, mesh_id}` → `202` /
     `409 not_identified` / `400 bad_envelope`. The unit stores `siot_inst.code` (bundle + name + zone).
   - `POST /enroll [{mac, id, name, zone}]` — board only; persisted immediately (`enrolled_n`/`enrolled`)
     so it survives whichever order `/enroll` and `/provision` arrive in.
   - `GET /status` → `{state, detail}`, `state ∈ idle | identified | stored | joining | online | failed`.
4. After `/provision`: state `stored`; reboot into normal mode once `/status` has been polled at least
   once, or after 30 s. Node → `JOINING`, LED white solid, Mesh-Lite keeps scanning for the network by
   itself (no board yet = Case A). Board → raises the installation AP.
5. **The board is provisioned from its sticker exactly like a node** (blueprint rule 4, Case A step A3).
   The tablet then reads the code back with `GET_INSTALLATION` → `INSTALLATION` (never the PSKs).
   Case B (tablet creates the code, `SET_INSTALLATION 0x11`) is undefined on the wire — §14.
6. Factory reset (button ≥ 5 s, both images): erase `siot_inst`, keep `nvs_factory`, reboot to step 1.

## 8. Board: `coordinator` (from `root_duties.c`, `tcp_link.c`, `board_main.c`)

- Normal mode only after a code exists: installation AP (§6.1), TCP server **`:5340`** (backlog 2, one
  client = the current root, newest wins, keepalive 5/2/3, single `select()` loop over listen + client,
  1 s tick), serial link (§6.5). Before that: setup mode, LED white blink.
- No 250-session question: the board never talks TCP to anything but the root. Scale is bounded by the
  AP's `max_connection` (8) during root election and by Mesh-Lite's tree — §14.
- **Root duties** (ported from `mocked-device/main/mesh_sim.c`): forward every valid uplink frame to the
  tablet byte-for-byte; ACK `COMMAND`/`TIME_SYNC` locally and forward them into the mesh; answer
  `GET_INSTALLATION` and `EVENT_LOG_REQ` locally; journal every uplink `EVENT` (`{jrn_seq, mac,
  payload[17]}`, 64-entry RAM ring in the POC — **flash-persisted in Phase 1**, spec §8); drop unknown
  downlink types silently.
- **Compatibility shim:** the board emits its own `HEARTBEAT` every 15 s and `TOPOLOGY` every 60 s with
  `LAYER 0`, `NODE_ROLE root`, `PARENT_MAC` = central; children = AC devices heard (Phase 1: drop after 180 s). The
  app's `meshLinkStateProvider` needs a layer-0 device to show "mesh connected". `SRC_MAC` = board STA MAC,
  `TTL 7`, `HOPS 0`, `boot_ctr` never 1 (reserved for the Appendix A vectors).
- `device_table` (Phase 1, replaces the POC's `children[8]`): keyed by MAC; serial/id, name, zone (from
  `NAME_ANNOUNCE` or the enrolled list), role, layer, parent, rssi, fw, state
  `enrolled / online / missing / retired`, last_seen. **`missing` after 3 × the device's heartbeat
  interval** (45 s powered, 180 s leaf) → synthetic `TROUBLE` "device missing" (blueprint §5.3). Today the
  app does this; Phase 1 moves it into the board and keeps the app's copy for the bench.
- Time source: central `TIME_SYNC` → board ACKs, forwards, and **adopts the epoch itself** (the POC
  board still sends `TIMESTAMP 0` in its own heartbeat) → nodes.

## 9. Supervision (`netcore`, node side) and LEDs

- Emitter cadence: `HEARTBEAT` 15 s, `TOPOLOGY` 60 s + on child change, `NAME_ANNOUNCE` once after join.
  **`NODE_BENCH_BUTTON_ONLY` must be 0** in Phase 1 (the bench build compiles these out and auto-fires
  `MANUAL_TEST` every 10 s instead).
- State transitions (§3) come from Mesh-Lite level, the board socket (root only) and ACK outcomes of
  critical EVENTs. There is no ack for heartbeats; a node cannot know it is "missing" — only the board
  can (§8).
- Every state change → bus event + LED pattern + `EVENT` to the board when reachable
  (`COMM_FAULT` TROUBLE when a critical uplink exhausts its fast phase; `RESTORE` when it recovers).

## 12. Exit checklist (Phase 1 is done when all pass on real boards)

1. Board with no code: setup mode (`SIOT-SETUP-<id>`, white blink); provisioned from its sticker with
   the enrolled list; on reboot the installation AP appears with the stored `net_ssid`/`channel`; tablet
   `GET_INSTALLATION` returns SYSTEM_ID, SSID, name and the enrolled names (no PSKs).
2. Node provisioned from a sticker QR with no board on site → `stored`, white solid; board appears
   later → node joins within 60 s without any user action and its `NAME_ANNOUNCE` reaches the tablet.
3. 2 AC nodes + board: mesh forms, root is the one with best RSSI to the board (level 1), the other at
   level 2; tablet lists both with correct layer/rssi/name/zone; board shim shows "mesh connected".
4. Power off the root → other node becomes root, socket recovers, tablet shows the dead node missing
   after ≈ 45 s and everything else back **median ≤ 60 s, max ≤ 120 s over 5 runs**; no ALARM lost when
   the survivor is double-tapped right after the cut.
5. `IDENTIFY` from the tablet to the level-2 node blinks it blue; `TEST` from the tablet produces a
   `MANUAL_TEST` on the tablet; the node's ACK for each command is visible in the tablet's serial log.
6. Replay a captured frame → dropped, `safr stats` replay counter increments; wrong `safr_psk` → auth
   failures, node never shows online; wrong `system_id` → counted as foreign, not decrypted.
7. Tap → `MANUAL_TEST` ALERT on the tablet with ACK **and the ACK delivered back to the node** (board
   forwards `ACK` frames downlink — a POC gap); double tap → ALARM latched, re-announced every 60 s
   as a single feed entry, `RESET` clears it only after the ACK; hold 5 s → factory reset → setup mode.
8. 24 h soak with 3 nodes: zero reboots, heap high-water stable, ≥ 99 % heartbeats, 0 CRC/auth failures.
9. `host` tests green in CI (vectors included); `hil/phase1.py` green.
10. `features/README.md` exists and a dummy feature component built against the frozen tree registers
    a new `MSG_TYPE` handler and an evbus subscriber without editing any Phase 1 file.

Tag the repo `fw-0.1.0` and freeze.

## 13. Freeze rules (how Phase 2+ add features without touching Phase 1)

- New features are new components that register SAFR handlers for **new** `MSG_TYPE`s / `CMD`s,
  subscribe to bus events, and add fields only to the **end** of existing payloads (with `VER`
  unchanged) or define new messages. Existing payload layouts are never edited; the spec is edited
  first, then the code (`safr_proto.h` header comment).
- New pins go into `board_def` via `pinmap.yaml`; `hal_*` gains functions, never changes signatures.
- `PWR_FLAGS`, `FAULT_FLAGS`, ACK `STATUS` and `LOG_FLAGS` reserved bits are the extension points;
  Phase 2 (tamper, battery), Phase 4 (OTA via the leaf `PENDING` path) use them.
- A Phase 1 file may change only for a bug, with a host or HIL test that reproduces the bug first.
- CI runs host tests on every commit and the HIL suite nightly on the bench rig.
